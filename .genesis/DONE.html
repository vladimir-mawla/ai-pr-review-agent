1 · The Locked Spec (what we are building)

Cognitive job: Automatically review GitHub pull requests the way a selective senior engineer would: run four specialist reasoners over the diff plus retrieved codebase context, and return one structured, evidence-backed review.

Inputs: A GitHub pull_request webhook event (HMAC-signed) carrying the PR diff, plus retrieved codebase context: embedded code chunks, past review history, and team conventions.  →  Outputs: A structured review made of typed Finding objects (agent type, severity, category, file/line, confidence, rationale), either posted to the PR or routed to a human approval queue.

Autonomy level: Level L3 on the Human-in-the-Loop spectrum: the system auto-handles routine, high-confidence findings and escalates only low-confidence or critical-severity cases.  |  Human-in-the-loop points: A human approval queue for any review below the confidence threshold or containing a CRITICAL finding, plus a developer dispute path that feeds corrections back into the system.

Failure tolerance: Must fail toward doing less, never toward guessing: on timeout or low confidence it defers to a human queue, and a retried webhook delivery must never post a duplicate review.  |  Trust boundary: Everything from GitHub (webhook payload and diff content) is untrusted until its HMAC signature verifies; all LLM output is untrusted until it validates against a Pydantic schema.

Filled during Genesis step G0 (Cognitive Design) via agentic-swe-master.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Dependency direction inward, zero cycles (modular-architecture gate)
Every outbound call has a timeout / circuit-breaker (production-readiness gate)
All LLM/structured outputs validated against a schema (llmops gate)
Threat model written; prompt-injection / untrusted-input considered (security gate)
mypy --strict backend/ clean AND pytest green in CI
One verify pass by a separate agent/model (L4)
No context-graph.json invariant violated by the change
Webhook HMAC-SHA256 verified and idempotency key checked before any work is enqueued (project gate)
LangGraph checkpoints actually resume after a simulated worker crash (compiled with a checkpointer, not without) (project gate)
Every security and reliability module has a live call site in the request path, provable by grep -- not merely a passing unit test (project gate)
Every CI job references test files that exist; CI is green on a clean checkout (project gate)
BudgetGuard hard-blocks the next LLM call once the daily cap is exceeded (project gate)
Findings dedupe by file and line, keeping highest confidence; aggregator threshold in code matches the threshold in its user-facing message (project gate)

A milestone is DONE only when every box above is checked by the verifier. Pull each gate from the relevant agentic-swe-master phase gate.
